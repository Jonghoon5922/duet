# Duet

나와 Claude가 함께 하는 일을 타스크로 묶고, 세션이 다 끝나면 타스크가 닫히는 **개인용 로컬 PMS**.
세션은 사람이 아니라 Claude가 열고 닫는다 — **MCP 서버 프로세스 하나 = 세션 하나.**

지금은 뼈대만 있는 프로토타입이다. 설계는 [SPEC.md](SPEC.md)에 있다.

## 저장

```
~/.duet/
├── T001-pc101pm-전환/
│   ├── task.md            제목·설명. 사람이 열어 고치는 파일
│   ├── s-a1b2c3d4.json    세션 A (그 프로세스만 쓴다)
│   └── s-e5f6a7b8.json    세션 B
└── _미참여/
    └── s-9f8e7d6c.json    아직 join 안 한 세션
```

DB가 없다. **한 파일에 두 주인이 없어서 락도 없다.**

- 세션 파일은 그 세션의 프로세스만 쓴다.
- `task.md`는 **편집만** 쓴다 — 사람이 화면·탐색기에서, Claude가 `update_task`로.
  양쪽 다 쓰지만 둘 다 누가 시켜서 한 번 일어나는 일이라 동시에 쏟아지지 않는다.
- 자동으로 도는 것(하트비트·참여·진행 보고·상태와 프로젝트 계산)은 `task.md`를 건드리지 않는다.

## 프로젝트

타스크는 프로젝트로 묶인다. **분류를 사람이 하지 않는다** — 세션이 뜬 폴더가 곧 프로젝트다.
`C:\project\nefss` 에서 띄운 Claude가 어떤 타스크에 join하면 그 타스크는 `nefss` 것이 된다.

`task.md`에 `프로젝트: 일지` 한 줄을 적으면 그것이 이긴다. 지우면 다시 센다 — 상태와 같은 방식이다.
보드는 프로젝트별로 묶어 보여주고, 지금 대시보드를 띄운 폴더의 프로젝트가 맨 위로 온다.

폴더 이름과 부르는 이름이 다르면 `~/.duet/프로젝트.md`에 한 줄 적는다:

```
C:\project\bookshelf = 서재
```

MCP는 클라이언트가 화면에 무슨 이름을 띄우는지 알려주지 않는다 — 앱마다 다르고 문서화된 계약도 아니다.
그래서 폴더를 근거로 삼고, 어긋나는 것만 한 줄로 맞춘다.

### 이름 짓는 기준

이 도구는 LLM을 부르지 않으므로, Claude를 움직이는 수단은 도구 설명뿐이다. 거기에 이렇게 박아 뒀다:

- **타스크**는 끝을 판정할 수 있는 한 덩어리. 결과물로 쓰고 대화로 쓰지 않는다
  (X `리팩터링 논의` / O `결제 모듈 리팩터링`). 세션 하나로 끝날 잔일이면 만들지 않는다.
- 제목에 **프로젝트 이름을 넣지 않는다.** 이미 묶여 있다 (X `Duet 대시보드 만들기` / O `대시보드 만들기`).
- **프로젝트는 만드는 것이 아니다.** 폴더가 곧 프로젝트다.
- `create_task`는 비슷한 제목이 열려 있으면 **만들지 않고 후보를 돌려준다.** 같은 일이면 거기에 join하고,
  정말 다른 일이면 `confirm=true`로 다시 부른다. 같은 일이 두 벌로 쌓이는 것이 제일 흔한 실수라서다.

## 규칙 셋

1. **타스크 상태는 저장하지 않고 센다.** 폴더 안 세션 파일을 세서 정한다.
   전부 `완료`면 `완료`, 하나라도 살아 있으면 `진행중`, 끊긴 세션이 남았으면 `확인 필요`
   (실패한 세션을 완료로 뭉개지 않는다). `보류`·`취소`는 사람만 정한다.
2. **사람이 정한 것이 이긴다.** `task.md`에 `상태: 완료` 한 줄을 넣으면 그게 상태다.
   그 줄을 지우면 다시 센다. 프로젝트도 똑같다.
3. **타스크 하나에는 살아 있는 세션 하나.** 두 창이 같은 일을 동시에 하면 같은 코드를 동시에
   건드린다. 이어받기는 앞 세션이 끝나거나 멈춘 뒤에 — `get_task`로 앞 로그를 읽고 붙는다.
   세션 하나는 타스크 하나다. 한 창이 타스크를 순서대로 여러 개 해도 되고, 그때마다 새 세션으로
   이어진다 (같은 창이라는 건 대화 id가 묶어 준다). 프로젝트 안에서는 창 여러 개가 각자 다른
   타스크를 동시에 한다.

세션은 30초마다 하트비트를 찍는다. 창을 닫으면 종료 훅이 `중지`로 적고,
훅조차 못 돌면(크래시·강제 종료) 하트비트 90초 초과를 읽는 쪽이 잡는다.

## 대시보드

```bash
duet ui        # http://127.0.0.1:8737
```

위에 상태별 집계 타일(누르면 필터), 아래에 **프로젝트 상자**. 상자 하나가 프로젝트 하나고 그 안에
타스크가 줄로 들어간다 — 줄에는 id·제목·세션 수·상태만 보이고, 누르면 설명·진행 막대·세션 줄·손잡이가
펼쳐진다. 세션 줄을 또 누르면 그 세션이 남긴 로그가 나온다. 제목·설명은 클릭해서 바로 고친다.
지금 대시보드를 띄운 폴더의 프로젝트가 맨 위다.

요청이 올 때마다 폴더를 다시 읽으므로, 탐색기에서 `task.md`를 고쳐도 2초 안에 화면에 뜬다.
화면에서 고치면 그 파일을 대신 써 준다 — 화면과 파일이 같은 것을 본다.
웹폰트도 CDN도 쓰지 않는다. 파일 감시(watchdog) + SSE는 아직이고, 지금은 2초마다 다시 물어본다.

### 사람이 손대는 자리

| 하는 일 | 어떻게 되나 |
|---|---|
| 세션 상태 바꾸기 (`중지` ↔ `완료`) | **끝난 세션만.** `확인 필요`인 타스크의 끊긴 세션을 완료로 바꾸면 자동 규칙이 다시 세서 타스크가 스스로 닫힌다 |
| 보관 / 되돌리기 | 폴더를 `~/.duet/_보관/`으로 옮긴다. 지우는 것이 아니라 언제든 돌아온다 |
| 상태 직접 정하기 | 드롭다운에서 고르면 `task.md`에 `상태:` 줄이 적혀 자동 규칙보다 앞선다 (🔒). 🔒를 누르면 그 줄이 지워지고 다시 센다. `확인 필요`는 고를 수 없다 — 세션이 끊겼다는 사실이다 |

**살아 있는 세션은 사람이 못 건드린다.** 그 파일의 주인은 그 프로세스이고, 그래야 락이 없는
구조가 안 깨진다. 도는 세션을 멈추는 것은 Claude가 `pause_session`으로 할 일이다.

## 시나리오

사람이 하는 것 → Claude가 알아서 하는 것 → 보드에 보이는 것.

**1. 첫 일** — `C:\project\nefss` 창을 열고 "pc101pm 화면 DBIO 전환해줘"
→ Claude가 `create_task("pc101pm 전환")` + `join_task`, 중간중간 `report_progress`, 끝나면 `complete_session`
→ 보드 `nefss` 섹션에 카드 하나. 세션 줄을 펼치면 로그. 세션이 하나뿐이라 끝나는 순간 `완료`.

**2. 이어받기** — 위 창에서 "여기까지만 하자" → Claude가 `pause_session("Service 계층 남음")`. 다음날 새 창에서 "pc101pm 이어서"
→ 새 창은 instructions에서 열린 타스크를 보고 `get_task`로 앞 로그를 읽은 뒤 `join_task`
→ 앞 세션은 `중지`로 남고 새 세션이 `진행중`. 둘 다 끝나면 `완료`.

**3. 창 둘, 다른 일** — 같은 프로젝트에서 창 A는 "DBIO 전환", 창 B는 "설계서 docx 빌드"
→ 각자 타스크를 만들어 붙는다. `create_task`가 비슷한 제목이 있으면 만들지 않고 후보를 주므로 두 벌로 쌓이지 않는다.
→ `nefss` 섹션에 카드 둘, 각각 세션 하나씩 `진행중`.

**4. 창 둘, 같은 일** — 창 A가 T001을 하는 중에 창 B에서도 "pc101pm 전환 이어서"
→ B의 `join_task`가 거절된다: *"[T001]에는 이미 살아 있는 세션이 있다 … 다른 창에서 하고 있는 게 아닌지 확인하라"*. Claude가 그대로 사용자에게 말한다.
→ 보드는 그대로. A가 끝내거나 멈춘 뒤에야 B가 붙는다.

**5. 한 창이 순서대로** — 창 하나에서 T001을 끝낸 뒤 "이제 docx 빌드 하자"
→ `join_task`가 새 세션으로 갈아타 T002에 붙는다. 앞 세션은 `완료`로 그대로.
→ T001 카드는 `완료`, T002 카드가 `진행중`. 두 세션 모두 같은 대화 id를 갖는다.

**6. 창을 그냥 닫음** — 보고 없이 창을 닫거나 크래시
→ 종료 훅이 `중지`로 적는다. 훅도 못 돌면 90초 뒤 읽는 쪽이 잡는다.
→ 타스크가 `확인 필요`가 된다. 세션 줄 드롭다운으로 `완료`로 바꾸면 타스크가 스스로 닫히고, 아니면 이어받을 창을 연다.

**7. 이름이 어긋남** — 폴더는 `bookshelf`인데 `서재`라고 부르고 싶다
→ `~/.duet/프로젝트.md`에 `C:\project\bookshelf = 서재` 한 줄.
→ 그 폴더에서 뜬 세션이 붙은 타스크가 전부 `서재` 섹션으로 옮겨 온다. 타스크 하나만 다르게 두려면 그 `task.md`에 `프로젝트: 서재`.

**8. 정리** — 완료 카드가 쌓였다
→ 완료된 타스크를 펼쳐 `보관함에 넣기`. 폴더가 `_보관/`으로 옮겨질 뿐 지워지지 않는다. `보관함` 버튼으로 보고 되돌린다.
→ 살아 있는 세션이 있는 타스크는 보관이 거절된다 — 먼저 닫는다.

**9. 사람이 억지로 정함** — 세션 상태와 무관하게 이 타스크는 완료로 치고 싶다
→ 드롭다운에서 `완료` (= `task.md`에 `상태: 완료`). 세션이 더 붙어도 안 바뀐다.
→ 🔒 표시. 🔒를 누르면 그 줄이 지워지고 다시 센다.

## 쓰기

프로젝트 `.venv`를 거치지 않는다. 셸마다 uv 데이터 폴더가 다를 수 있어 `.venv`가 한쪽에서는
멀쩡하고 다른 쪽에서는 "없는 인터프리터"가 되는 일이 실제로 있었다. `uv run`이 창이 열릴 때마다
환경을 맞추려 들면서, 떠 있는 duet 서버가 잡고 있는 `duet.exe`를 다시 쓰려다 막히기도 했다.
그래서 **독립 환경에 실행 파일로** 깐다. 소스는 editable이라 코드를 고치면 바로 반영된다.

```bash
uv tool install --editable --python 3.12 C:/project/duet
uv tool update-shell          # ~/.local/bin 을 PATH에 (한 번만)
```

그다음 사용자 범위로 한 번 등록하면 **모든 프로젝트 창**에서 붙는다. 창마다 할 것은 없다.

```bash
claude mcp add -s user duet -- duet serve
```

(`duet`가 PATH에 없으면 `C:\Users\<이름>\.local\bin\duet.exe` 전체 경로로.)

의존성을 바꿨을 때만 `uv tool install --editable --reinstall C:/project/duet`.
개발 중 테스트는 `uv sync --group dev` 뒤 `uv run --no-sync pytest`.

MCP 도구: `list_tasks` · `create_task` · `join_task` · `get_task` · `update_task` · `report_progress` · `complete_session` · `pause_session`

`get_task`가 인수인계다 — 세션 B가 A의 진행 로그를 읽고 이어받는다.
`pause_session`은 "여기까지"일 때. 중지된 세션이 있으면 타스크는 닫히지 않는다.
`update_task`는 사용자가 시켜서 제목·설명·상태를 고칠 때. 폴더 이름은 그대로 둔다.
CLI: `duet serve` · `duet ui` · `duet add` · `duet list` · `duet show` · `duet version`

```bash
uv run pytest && uv run python scripts/smoke.py
```

`smoke.py`는 진짜 stdio 서버 프로세스를 여러 개 띄워 한 바퀴 돌린다.
단위 테스트가 못 보는 것(프로세스가 죽을 때 무슨 일이 벌어지는가)을 본다.
