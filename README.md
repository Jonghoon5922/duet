# Duet

Claude Code 창에서 한 일이 **저절로 기록되는 개인용 보드.**
창을 열고 평소처럼 일을 시키면, Claude가 타스크를 만들고 붙고 진행을 남기고 끝내면 완료 보고를 한다.
보드는 그걸 프로젝트별로 보여준다. DB도 서버도 계정도 없다 — 내 PC의 폴더 하나가 전부다.

```
duet                                  ← 프로젝트 = Claude 창을 연 폴더
  T001  파일 감시 + SSE로 폴링 걷어내기        Done
  T002  설치 한 번으로 끝나게                  Done
  T003  Feedback 버튼 — GitHub 이슈로          Running   ● Claude Code · working
tokenbill
  T001  커뮤니티 공개 (GeekNews·해외 채널)      Needs review
```

---

## 1. 받기와 설치 (Windows)

준비물은 **Claude Code**뿐이다. 파이썬도 uv도 필요 없고 관리자 권한도 묻지 않는다.

1. [Releases](https://github.com/Jonghoon5922/duet/releases/latest)에서 `duet-setup-<버전>.exe`를 받는다.
2. 실행한다. "Claude 창을 모두 닫아 주세요" 안내가 뜨면 열린 Claude 창을 닫고 [확인].
3. "Claude Code에 연결합니다"가 켜진 채로 [설치].

끝. `내 사용자 폴더\Duet\`에 깔리고, Claude Code 설정(`~\.claude.json`)에 Duet이 등록된다.
이 등록은 컴퓨터를 껐다 켜도 남는다. 새 버전은 같은 방법으로 덮어 설치한다.

제거는 제어판 → 앱 → Duet. 실행 파일과 연결이 지워지고 **기록(`~\.duet`)은 남는다.**

## 2. 붙었는지 확인

Claude Code 창을 새로 열고 이렇게 물어본다:

> duet 도구 있어?

타스크 목록이 나오면 붙은 것이다. (`/mcp`를 쳐도 된다 — `duet ✔`)

보드는 브라우저에서 **http://127.0.0.1:8737**. Claude 창이 하나라도 열려 있으면 켜져 있다.
창이 하나도 없을 때는 시작 메뉴 [Duet 보드]를 누르면 뜬다 (10분 동안 안 보면 스스로 꺼진다).

터미널에서 보려면:

```powershell
& "$env:USERPROFILE\Duet\duet.exe" mcp-list
```

## 3. 쓰는 법 — 따로 배울 게 없다

**프로젝트 폴더에서 Claude Code 창을 열고 평소처럼 일을 시킨다.** 그게 전부다.

- 폴더 이름이 곧 프로젝트다. `C:\project\nefss`에서 연 창의 일은 보드의 `nefss` 상자에 쌓인다.
- Claude가 알아서 타스크를 만들거나(`T001`부터 번호) 열린 타스크에 붙고, 일하면서 한 줄씩 남기고, 끝나면 완료 보고를 한다.
- 창을 여러 개 열면 창마다 다른 타스크를 동시에 한다. 같은 타스크에는 한 번에 한 창만 붙는다.

Claude에게 이렇게 말하면 된다:

| 이렇게 말하면 | 이렇게 된다 |
|---|---|
| "○○ 만들어줘" | 타스크를 만들고 붙어서 일하고, 끝나면 Done |
| "○○ 계획 세워줘" | 계획을 보여주면서 **그 자리에서 타스크를 만든다** (계획 요지가 설명에 들어간다) |
| "타스크 순서대로 진행해줘" | 하나 끝내고 다음에 붙는다. 보드에서 Running이 한 줄씩 내려간다 |
| "T003 이어서 해줘" | 앞 창이 남긴 로그를 읽고 이어받는다 |
| "여기까지만 하자" | 세션을 멈춘다. 타스크는 Needs review로 남아 다음 창이 이어받는다 |
| "타스크에 넣어" | Claude가 타스크를 안 만들었을 때 한마디로 만들게 한다 |
| "tokenbill 프로젝트에 타스크 만들어줘" | 다른 프로젝트 것을 대신 만든다 |

## 4. 보드에서 하는 일

보드는 **보고 정리하는 곳**이다. 일은 Claude 창에서 한다.

- **프로젝트 상자** — 머리를 누르면 접히고 다시 누르면 펴진다. 최근에 움직인 프로젝트가 위.
- **타스크 줄** — 누르면 설명·세션·진행 로그가 펼쳐진다. 제목과 설명은 클릭해서 고친다. 번호순.
- **상태** — 세션에 따라 저절로 정해진다: Waiting(아직 안 붙음) → Running(창이 일하는 중) → Done.
  창이 보고 없이 닫히면 **Needs review** — 세션 줄 드롭다운에서 Done으로 치거나, 새 창에서 이어받는다.
  직접 정하고 싶으면 드롭다운에서 Done·On hold·Cancelled (🔒가 붙는다. 🔒를 누르면 다시 자동).
  **Claude가 일하는 중인 타스크는 잠긴다** — 끝나면 풀린다.
- **상태 칩** (All / Waiting / Running / …) — 누르면 그 상태만. **검색**은 제목·설명·로그까지 뒤진다.
- **+ New Project** — 이름과 첫 타스크. 빈 프로젝트는 안 만든다.
- **+ Task** (상자 머리) — 그 프로젝트에 타스크를 미리 적어 둔다. Claude가 나중에 붙는다.
- **Archive** (상자 머리) — 끝난 프로젝트를 상자째 치운다. 지우지 않는다. 오른쪽 위 **Archived**에서 보고 **Unarchive**로 되돌린다.
- **×** — 잘못 만든 타스크·프로젝트를 지운다. 확인창을 거치고, 살아 있는 세션이 있으면 거절된다.
- **Feedback** — 제목·내용을 적으면 GitHub 새 이슈 화면이 채워진 채 열린다 (GitHub 계정 필요).

화면은 폴더가 바뀔 때 저절로 갱신된다. 새 버전을 깔면 열린 탭도 스스로 새로고침한다.

## 5. 자주 묻는 것

**컴퓨터를 껐다 켜면 다시 연결해야 하나?** 아니다. 등록은 설정 파일에 남는다.

**Claude 창마다 `duet.exe`가 하나씩 뜨는데?** 그게 설계다. 창 하나 = 세션 하나. 가볍고, 창이 닫히면 같이 사라진다.
보드는 그중 하나가 맡고, 그 창이 닫히면 다음 창이 이어받는다.

**타스크가 Waiting이었는데 갑자기 Needs review가 됐다.** 어떤 창이 붙었다가 보고 없이 닫힌 것이다.
세션 줄을 펼치면 어느 창이 언제 붙었는지 보인다. 끝난 일이면 Done으로 치면 된다.

**Claude가 타스크를 안 만들고 그냥 일했다.** 안내문은 지시지 강제가 아니라 가끔 빠진다. "타스크에 넣어" 한마디면 된다.
한두 마디로 끝날 잔일은 원래 타스크를 안 만든다.

**재설치할 때 창을 다 닫아야 하나?** 지금은 그렇다. 창마다 뜬 `duet.exe`가 파일을 잡고 있어서다. 보드 탭도 닫는다 (`duet-board.exe`가 안 꺼진다).

**Claude 데스크탑 채팅 탭에서도 되나?** 붙긴 하지만 폴더가 없어서 타스크가 `_미분류`로 가고 안내문을 덜 따른다. Duet은 **Code 탭(Claude Code)** 용이다.

**기록은 어디에?** `내 사용자 폴더\.duet\<프로젝트>\T00n-제목\` 아래 `task.md`(제목·설명)와 `s-*.json`(세션·로그).
탐색기에서 열어 읽고 고쳐도 된다. 폴더 이름과 다른 이름으로 부르고 싶으면 `.duet\프로젝트.md`에 `C:\project\bookshelf = 서재` 한 줄.

## 어떻게 돌아가나

이 아래는 설계 이야기다. 쓰는 데는 필요 없다.

### 저장

```
~/.duet/
├── nefss/                     프로젝트 = 폴더
│   ├── T001-pc101pm-전환/
│   │   ├── task.md            제목·설명 (+ 사람이 정한 상태 한 줄)
│   │   ├── s-a1b2c3d4.json    세션 A (그 프로세스만 쓴다)
│   │   └── s-e5f6a7b8.json    세션 B
│   └── T002-설계서-docx-빌드/
├── _미분류/                   어느 프로젝트인지 못 알아낸 타스크
├── _미참여/                   아직 join 안 한 세션
├── _보관/                     끝난 프로젝트를 폴더째 옮겨 두는 곳
└── 프로젝트.md                폴더 경로 = 부르는 이름
```

DB가 없다. **한 파일에 두 주인이 없어서 락도 없다.**
세션 파일은 그 세션의 프로세스만 쓴다. `task.md`는 편집만 쓴다 — 사람이 화면·탐색기에서, Claude가 `update_task`로.
자동으로 도는 것(하트비트·참여·진행 보고·상태 계산)은 `task.md`를 건드리지 않는다.

### 규칙 셋

1. **타스크 상태는 저장하지 않고 센다.** 세션 파일을 세서 정한다. 전부 `완료`면 `완료`, 하나라도 살아 있으면 `진행중`,
   끊긴 세션이 남았으면 `확인 필요`. 사람이 고르는 것은 `완료`·`보류`·`취소` 셋뿐이다.
2. **사람이 정한 것이 이긴다.** `task.md`에 `상태: 완료` 한 줄이 있으면 그게 상태다. 지우면 다시 센다.
3. **타스크 하나에 살아 있는 세션 하나, 세션 하나에 타스크 하나.** 이어받기는 앞 세션이 끝나거나 멈춘 뒤에 —
   `get_task`로 앞 로그를 읽고 붙는다. 한 창이 순서대로 여러 타스크를 하면 그때마다 새 세션이다.

세션은 30초마다 하트비트를 찍는다. 창을 닫으면 종료 훅이 `중지`로 적고, 훅조차 못 돌면 90초 초과를 읽는 쪽이 잡는다.
파일 이름과 도구는 한글 상태 이름을 쓰고, 보드는 화면에서만 영문으로 보여준다.

### Claude를 움직이는 방법

이 코드는 LLM을 부르지 않는다. Claude를 움직이는 수단은 창이 열릴 때 넘어가는 **안내문**과 **도구 설명**뿐이고, 거기에 이렇게 박아 뒀다:

- 모든 일은 타스크를 타고 간다. 계획을 보여주는 순간 타스크를 만든다.
- 타스크는 끝을 판정할 수 있는 한 덩어리. 결과물로 쓰고 대화로 쓰지 않는다 (X `리팩터링 논의` / O `결제 모듈 리팩터링`).
- 제목·설명·로그는 사용자가 쓰는 말로, 사람 메모처럼. 번호 매기기·괄호 설명 금지.
- 비슷한 제목이 열려 있으면 만들지 않고 후보를 돌려준다. 같은 일이 두 벌로 쌓이는 것이 제일 흔한 실수라서다.
- 프로젝트는 따로 만들지 않는다. 창이 뜬 폴더가 곧 프로젝트고, 첫 타스크와 함께 생긴다.

### 왜 실행 파일로 묶었나

셸마다 uv 데이터 폴더가 다를 수 있고, Claude 데스크탑 안 터미널은 `AppData`가 앱 전용 폴더로 바뀌어 보인다.
`.venv`도 uv 트램폴린도 거기서 깨졌다. PyInstaller로 파이썬째 묶은 실행 파일은 그런 것에 기대지 않는다.
설치 위치도 그래서 `AppData` 밖이다. 실행 파일이 둘이다 — `duet.exe`(콘솔, MCP는 stdio가 필요하다)와 `duet-board.exe`(창 없음, 보드).

## 개발

```bash
uv sync --group dev
uv run --no-sync pytest                       # 단위 테스트
uv run --no-sync python scripts/smoke.py      # 진짜 stdio 서버 프로세스로 한 바퀴
uv run --no-sync python scripts/build.py      # 검사 전부 → PyInstaller → Inno Setup → dist/duet-setup-<버전>.exe
```

`build.py`는 테스트·스모크·import·묶인 exe 기동을 통과해야 인스톨러를 만든다. 버전은 `src/duet/__init__.py` 한 곳.

개발 중인 코드를 Claude Code에 붙이려면:

```bash
uv tool install --editable --python 3.12 C:/project/duet   # ~/.local/bin/duet.exe
duet mcp-register                                           # Claude Code 사용자 범위
```

MCP 도구: `list_tasks` · `create_task` · `join_task` · `get_task` · `update_task` · `report_progress` · `complete_session` · `pause_session`
CLI: `duet serve` · `duet ui` · `duet add` · `duet list` · `duet show` · `duet version` · `duet mcp-register` · `duet mcp-unregister` · `duet mcp-list`

설계 초안은 [SPEC.md](SPEC.md), 진행 상태는 [CLAUDE.md](CLAUDE.md).
